# Information Model

The **Information Model** (as referenced in ISO 19650) is not a single item but a collection of different types of project outputs. 

Depending on the phase of the project, it is referred to differently:
- **PIM (Project Information Model)**: Used during the design and construction phases.
- **AIM (Asset Information Model)**: Used during the operation and maintenance phases.

## Components of the Information Model

The information model encompasses three main types of data:

### Geometric Data
Information expressed using shape, size, dimension, detail, location, appearance, and parametric behaviour. Objects in the model act as a container for meta-data and are dimensionally accurate for spatial coordination and clash detection.

### Non-Geometric / Alphanumeric Data
Meta-data associated with an object within a BIM model, expressed via tokens, symbols, characters, or digits. Examples include databases, spreadsheets (e.g., COBie), specifications, product data, and information from web services. 

### Documentation
Static documents that support processes, decisions, approvals, and verification of information deliverables. Examples include drawings, schedules, bills of quantities, warranties, and appointments.
- Documents should be named appropriately according to a local appendix or project-specific standard.
- The main problem with static documentation (like PDFs) is the difficulty of searching for data within them.
